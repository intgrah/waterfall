Configuration & interfaces

A small public tactic, with ordinary Lean functions underneath.

Tactic options

Use individual configuration items, or (config := {mode := .search, effort := 3000}).

OptionDefaultBehavior
mode.searchBacktracking search or ACL2-inspired .committed.
cpus1Maximum concurrent trials. Total effort and heartbeats remain shared. One CPU preserves sequential execution.
effort1000Global operation allowance, across trials and failed alternatives.
attemptHeartbeats20000000Base raw heartbeat slice per operation; trial strength scales it.
lazytrueGenerate each batch only when reached. False enumerates phase batches eagerly.

Programmatic configuration

Waterfall.run accepts engine configuration, supplied rule syntax and Hooks. Adapt Mode.search.hooks or Mode.committed.hooks to experiment without changing the inference engine.

example (P : Prop) (h : P) : P := by
  run_tac discard <| Waterfall.run {} #[]
    { Waterfall.Mode.search.hooks with
      trials := Waterfall.diagonalTrials 1 }

trials chooses depth and strength pairs. order permutes candidate selectors within a batch. cost assigns goal-aware path costs. extraMoves appends general operations. The engine validates order permutations and structural cost floors.

Choose transitions with a policy

SearchPolicy.choose selects an ordered lazy sequence of Node checkpoints. Typed policy state can hold an explicit frontier. Space.expand supplies metered transitions for any pending goal; Space.restart restores a whole checkpoint and charges work.

Each checkpoint owns compatible Lean state, sibling obligations, per-goal ancestry and its retained proof path. Choices.first commits, filter restricts choices, and collect materializes offered successors. Collection pays their cost. Arbitrary callbacks are trusted metaprograms and can make search unfair.

Tested policies include FIFO and scored successor selection, as well as shared-witness and frontier-exhaustion regressions.

Parallel execution

Waterfall.Parallel.run distributes rounds of the same policy across isolated workers. Its callback initializer creates separate mutable observers for each worker. The first complete proof wins, then remaining workers are cancelled and joined. Cancellation is cooperative. Dedicated worker threads also work when the caller runs inside Lean’s elaboration task pool.

A fixed budget can produce different coverage; expensive work inside one trial is still sequential. See the resource and callback contract.

Observe and replay

Waterfall.Observe provides capture, Control and replay. Timing rows report inclusive and exclusive nanoseconds and raw heartbeats. Control middleware can reduce per-span slices or enforce cooperative deadlines.

Plans record versioned operation selectors, agenda positions, input encodings, costs and generated-child counts. Replay checks those against the same source, rules and hooks. It executes the retained route without looking for alternatives. Unresolved roots are rejected; Lean checks the final proof.
