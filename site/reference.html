Tactic options

Both waterfall and waterfall? accept individual options or a structure such as (config := {mode := .search, effort := 3000}).

OptionDefaultBehavior
mode.searchBacktracking search or ACL2-inspired .committed.
cpus1Maximum concurrent workers, with a shared total budget.
effort1000Number of attempts across all trials, including failures.
attemptHeartbeats20000000Base raw heartbeat slice per operation; trial strength scales it.
lazytrueTrue generates a batch when search reaches it; false generates all batches in a phase up front.
deferChecksfalseTrue postpones applicability checks until a candidate is considered.
reportfalseTrue prints search statistics.

Hooks

Waterfall.run takes a Config, supplied rules and Hooks. The hooks separate traversal, candidate ordering, path costs and the depth/strength schedule from inference. For example, the default policy can retain its inference behavior with a different trial prefix:

example (P : Prop) (h : P) : P := by
  run_tac discard <| Waterfall.run {} #[]
    { Waterfall.Mode.search.hooks with
      trials := Waterfall.diagonalTrials 1 }

trials enumerates depth/strength pairs. order returns a permutation of stable candidate selectors, checked by the engine. cost assigns path costs subject to structural lower bounds; extraMoves appends inference candidates without changing existing selectors. Goal-aware ordering and cost callbacks run in the input context under proof-state rollback.

Policies and proof state

A Node contains a compatible saved Lean state, the conjunctive goal agenda, per-goal ancestry, the retained proof path and typed policy state. SearchPolicy.choose returns a lazy sequence of successor checkpoints; the policy state can carry an explicit frontier.

Space.expand supplies metered transitions for a selected goal while preserving its siblings. Space.restart restores a complete checkpoint with replacement policy state and charges one attempt. Traversal never merges independently proved siblings with incompatible metavariable assignments.

Choices.first implements commitment; filter restricts successors; collect materializes them for explicit frontier management. Materialization executes the transitions and incurs their metered cost.

The policy tests include FIFO and scored selection. Fairness depends on the policy and trial enumeration. Proof-state rollback does not undo external IO effects in callbacks.

Workers

Waterfall.Parallel.run schedules trials with isolated Lean state and worker-local observers. Only a complete proof is adopted; cancellation and joining account for work spent by losing workers.

The API notes describe the budget accounting and callback initialization.

Timing and replay

Waterfall.Observe is an optional import. capture records inclusive and exclusive timings, raw heartbeats and the accepted plan. Control can reduce per-operation limits or impose a cooperative deadline.

replay interprets the retained plan, validating operation selectors, agenda positions and generated-child counts against the recording. It requires the same source, rules and hooks, and rejects unresolved original obligations. This is exact-plan replay rather than reconstruction by another search.
