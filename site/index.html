Proof search for Lean

Waterfall is a Lean tactic for inductive proofs. It searches for combinations of simplification, lemma application, case analysis and induction, using Lean to check the resulting proof.

Version 0.1 is a private release candidate. It depends only on Lean 4.33.1 and uses the Apache-2.0 license.

Software Foundations · VFA / SearchTree

Equivalence of two tree traversals

The following theorem, adapted from Software Foundations, relates an in-order traversal using list append to an accumulator implementation:

theorem fast_elements_helper (t : Tree V) (acc : List (Nat × V)) :
    fastElements t acc = elements t ++ acc := by
  waterfall [elements, fastElements, List.append_assoc]

The bracketed arguments supply the two definitions and append associativity. Waterfall finds an induction proof that accounts for the changed accumulator in recursive calls.

Complete Lean example 
import Waterfall

inductive Tree (V : Type) where
  | empty
  | node (left : Tree V) (key : Nat) (value : V) (right : Tree V)

def elements : Tree V → List (Nat × V)
  | .empty => []
  | .node left key value right => elements left ++ (key, value) :: elements right

def fastElements : Tree V → List (Nat × V) → List (Nat × V)
  | .empty, acc => acc
  | .node left key value right, acc =>
      fastElements left ((key, value) :: fastElements right acc)

theorem fast_elements_helper (t : Tree V) (acc : List (Nat × V)) :
    fastElements t acc = elements t ++ acc := by
  waterfall [elements, fastElements, List.append_assoc]

Adapted from VFA. This complete example is checked on Lean 4.33.1 and 4.30.0. Proof explanation

Usage

import Waterfall makes waterfall and waterfall? available. Either tactic can prove a whole theorem or close a remaining goal after manual proof steps. Local hypotheses are used automatically; definitions and helper lemmas can be supplied in brackets.

waterfall? also produces a checked “Try this” editor hint. Accepting the hint replaces the invocation with ordinary Lean proof commands. Those commands may still use simp_all or grind for individual goals.

The Software Foundations examples contain three complete developments:

  • Expression optimization (LF / Imp): removing 0 + e preserves evaluation.
  • Insertion sort (VFA / Sort): insertion preserves sortedness and permutation. The full sorting proof combines Waterfall with a short explicit permutation argument.
  • Tree traversal (VFA / SearchTree): the accumulator implementation returns the same elements as the simple traversal.

Each development proves its own helper lemmas and imports only Waterfall. The Lean source is part of the test suite.

How it works

Waterfall proposes proof steps from the goal, local context and available lemmas. These include applying a theorem backward, instantiating a hypothesis, splitting a case, and inducting on data or a recursive call. Simplification, arithmetic and grind close simpler goals. Candidates are generated as the search reaches them.

The default search follows a candidate through all its resulting obligations. If a later obligation fails, it restores the earlier proof state and tries another candidate. Trials allow progressively deeper proofs and stronger individual operations, subject to a shared effort allowance.

Committed mode uses the same proof operations with an ACL2-inspired policy: it accepts local progress, tries ordinary proof steps before induction, and can return to the original conjecture once per trial. It discards alternatives, so it can miss proofs that backtracking finds.

Missing helper lemmas, difficult mutual induction and search ordering remain common obstacles. The package does not perform lemma discovery or implement all of ACL2’s reasoning machinery.

The reference describes the search interfaces, optional timing and action recording, and proof-plan replay.

Main options

Configuration items precede the optional list of definitions and lemmas. For example:

waterfall (mode := .committed) (effort := 3000)
  [elements, fastElements, List.append_assoc]
OptionDefaultMeaning
mode.searchBacktracking search, or .committed for commitment after local progress.
effort1000Total attempted-operation allowance, including failed attempts. Larger values also permit deeper plans and stronger operations.
cpus1Maximum concurrent workers. Workers explore different trials of the same policy and share the total budget.
reportfalseWhether to print search statistics.

Both tactics accept these options. Lean’s enclosing heartbeat and recursion limits still apply. More effort need not make a proof faster, and parallel execution can change which proofs are found within a fixed budget.

The full option reference also covers per-operation heartbeats, lazy enumeration and deferred applicability checks.

Installation

The 0.1.0 Lake package is in the private samth/Waterfall repository. Public distribution and Reservoir registration are pending. A project with the Waterfall checkout in a sibling directory can use this dependency in lakefile.toml:

[[require]]
name = "waterfall"
path = "../Waterfall"

The two projects need the same lean-toolchain. After lake update, the package is available through import Waterfall. The release targets Lean 4.33.1; compatibility is also tested on Lean 4.30.0.
