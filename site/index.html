Waterfall

Waterfall searches for induction proofs in Lean. It uses simp and grind on subgoals, and backtracks over choices of induction, case analysis and lemma application.

For example, this theorem from Software Foundations relates two tree traversals:

theorem fast_elements_helper (t : Tree V) (acc : List (Nat × V)) :
    fastElements t acc = elements t ++ acc := by
  waterfall [elements, fastElements, List.append_assoc]

elements builds its result with list append; fastElements carries an accumulator. The recursive calls change the accumulator, so the induction has to account for more than its initial value. Waterfall finds that proof given the two definitions and append associativity.

Definitions and complete proof 
import Waterfall

inductive Tree (V : Type) where
  | empty
  | node (left : Tree V) (key : Nat) (value : V) (right : Tree V)

def elements : Tree V → List (Nat × V)
  | .empty => []
  | .node left key value right => elements left ++ (key, value) :: elements right

def fastElements : Tree V → List (Nat × V) → List (Nat × V)
  | .empty, acc => acc
  | .node left key value right, acc =>
      fastElements left ((key, value) :: fastElements right acc)

theorem fast_elements_helper (t : Tree V) (acc : List (Nat × V)) :
    fastElements t acc = elements t ++ acc := by
  waterfall [elements, fastElements, List.append_assoc]

import Waterfall makes the tactic available. Definitions and lemmas go in brackets; local hypotheses are used automatically. waterfall? produces a checked proof script that can replace the tactic call through Lean’s “Try this” hint.

Search and commitment

The project draws on ACL2’s approach to automation: simplification and lemma use prepare a conjecture for induction, and the resulting subgoals go through the same process.

Waterfall’s default mode backtracks. If an induction closes two cases but gets stuck on the third, search can undo the induction and try something else. Each trial limits proof depth and the work allowed for individual operations; later trials raise those limits.

(mode := .committed) follows a policy closer to ACL2. It commits to a step once that step makes progress, even if a later subgoal fails. It postpones induction until other steps fail, and can return to the original conjecture once per trial.

The two modes share the proof engine. Search policy and timing and recording are separate from the proof operations. Lemma discovery remains outside this package.

Options

waterfall (mode := .committed) (effort := 3000)

OptionDefaultEffect
mode.search.committed disables backtracking after local progress.
effort1000Number of attempts available across the whole search, including failures.

reportfalsetrue prints search statistics.

A larger effort gives the search more attempts and access to deeper proofs and stronger solvers. It may take longer. Lean’s maxHeartbeats and maxRecDepth limits also apply.

waterfall? accepts the same options. The reference includes controls for per-step budgets and candidate enumeration.

Software Foundations

We tested 53 goals from six chapters of Verified Functional Algorithms:

Successes include selection-sort permutation, merge-sort sortedness, red-black-tree lookup preservation and binomial-heap validity. Every successful waterfall? replacement was compiled separately.

This run used Lean 4.30.0, effort 10,000 and 800M raw heartbeats. The goals were selected during development, with preceding helper facts supplied as assumptions. The counts describe that test set, not coverage of the books or performance on held-out goals. We have not repeated this run on Lean 4.33.1.

The test report and per-goal results give the details.

The examples are smaller proofs from LF and VFA: an expression optimizer, insertion sort and the tree traversal above. They import only Waterfall and prove their own helper lemmas. The sorting example also shows a step that we still prove by hand.

Lake package

Version 0.1.0 is in the private samth/Waterfall repository; public release and Reservoir registration are pending. With the checkout next to a Lean project, its lakefile.toml dependency is:

[[require]]
name = "waterfall"
path = "../Waterfall"

Both projects need the same lean-toolchain. lake update resolves the dependency. Waterfall has no dependencies beyond Lean; version 0.1 targets Lean 4.33.1 and is also tested on 4.30.0.
